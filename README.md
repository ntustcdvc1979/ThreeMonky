# 三隻猴子 🙊🙉🙈

三人一組的傳話遊戲。話從第一個人傳到第三個人，還會剩下多少？

- 🙊 **比劃猴** — 拿手機看題目。只能比手畫腳，發出任何一個字就算犯規。
- 🙉 **傳話猴** — 背對題目，只看得到比劃猴的動作。用嘴巴講給猜題猴聽。
- 🙈 **猜題猴** — 閉眼背對。只能用聽的，然後把聽到的東西**畫在紙上**。

純靜態網頁，**沒有後端、沒有資料庫**。`git push` 就是部署。

## 兩個畫面

| 網址 | 誰用 | 做什麼 |
|---|---|---|
| `https://<帳號>.github.io/ThreeMonky/` | 主持人的筆電，接投影機 | 規則、站位、大倒數、時間到 |
| `.../ThreeMonky/play.html` | **每組的比劃猴各一支手機** | 抽題、出題、揭曉答案 |

**兩個畫面完全不通訊。** 題庫打包在網頁裡，各組自己抽題、自己揭曉，投影幕只負責全場共同的節奏。所以：

- 投影幕上**不會出現任何正式題目**（只有範例題「太陽」），台下偷看也沒用。
- 答案是在**比劃猴自己的手機上**炸出來給那一組看。
- **沒有分數排行榜**。手機會顯示自己這組答對幾題，如此而已。

## 現場怎麼跑

### 活動前

1. 手機開一次 `play.html`，確認載得進來（第一次載完就會存進離線快取）。
2. 筆電接投影機，開投影端，按 <kbd>F</kbd> 全螢幕。
3. 場地偏暗的話按 <kbd>C</kbd> 切暗場。

### 當天

1. **封面** — 每組派一個人當比劃猴，掃 QR。QR 掃不到就直接念底下那行網址。
2. **規則 / 站位** — 三隻猴子各自的限制、站成一直線。
3. **範例題** — 找一組上台用「太陽」示範一次。
4. **交接** — 比劃猴在手機上選組號、選難度，然後**等你喊開始**。
5. **正式輪** — 按 <kbd>S</kbd> 跑 3・2・1，倒數自動開始。各組在時間內連續闖題。
6. **時間到** — 按 <kbd>→</kbd> 翻到 hype 畫面，猜題猴睜眼、大家看畫。
7. 重複 5–6。預設三輪，不夠按 <kbd>Esc</kbd> → 「➕ 再加一輪」。

> **選組號很重要。** 各組選了不同組號，系統才會把牌堆錯開，隔壁組不會跟你同時比一樣的題目。

## 投影端鍵盤

| 鍵 | 動作 |
|---|---|
| <kbd>→</kbd> <kbd>空白</kbd> <kbd>Enter</kbd> | 下一頁 |
| <kbd>←</kbd> | 上一頁 |
| <kbd>Esc</kbd> | 跳關選單（也能從這裡再加一輪） |
| <kbd>F</kbd> | 全螢幕 |
| <kbd>S</kbd> | 3・2・1 開始，跑完自動接上倒數 |
| <kbd>T</kbd> | 倒數 開始 / 暫停 |
| <kbd>R</kbd> | 倒數重設回本輪預設秒數 |
| <kbd>+</kbd> <kbd>-</kbd> | 加 / 減 30 秒 |
| <kbd>1</kbd> <kbd>2</kbd> <kbd>3</kbd> | 本輪設成 2 / 2.5 / 3 分鐘並重新開始 |
| <kbd>C</kbd> | 亮場 / 暗場 |
| <kbd>H</kbd> | 收起 / 打開角落的小 QR |
| <kbd>M</kbd> | 靜音（嗶聲） |

加時對各組是**自動生效**的——手機端根本不計時，全場只看投影幕這一個鐘。

## 改題目

題目全部在 [`assets/terms.js`](assets/terms.js)，那支檔案裡沒有任何邏輯，放心改。

```js
{ id: "t305", t: "掃地機器人卡在椅腳", lv: 3, cat: "場景", hint: "圓盤子、椅子腳、原地轉圈" },
```

- `id` — 不能跟別題重複。之後插新題不要改舊的 id（手機的存檔認 id）。
- `lv` — 1 暖身 / 2 進階 / 3 地獄 / 4 自己人，決定它會被分到哪個難度。
- `hint` — 選填，只在揭曉畫面顯示「畫重點：⋯」。長場景題建議都給。
- **挑題原則**：最後一關是閉著眼睛聽描述、把它畫出來，所以只收**畫得出輪廓的具象詞**。抽象詞（誠實、努力、友情）猜題猴會直接罷工。

目前 74 題：暖身 18、進階 20、地獄 22、自己人 14。

> **題庫要夠大。** 系統靠「把洗好的牌堆錯開發給各組」來避免撞題，錯開的間距是 `該難度的題數 ÷ 12`。只勾一個難度時池子太小，隔壁組就很可能跟你比到一樣的——手機上會跳提醒要你多勾一個。抓個大概：**該難度題數 ÷ 組數 ≥ 4** 才安全。

改完直接 `git push`，GitHub Actions 會自動部署。頁面用 stale-while-revalidate 快取，所以**手機重整一次會拿到新版**（第一次重整還是舊的、第二次才是新的，這是快取策略的正常行為）。要強制清掉所有舊檔，把 [`sw.js`](sw.js) 最上面的 `CACHE = "tm-v1"` 版號 +1。

## 部署

**第一次要手動開一次 Pages**：去 **Settings → Pages → Source** 選 **GitHub Actions**，然後回 Actions 頁把失敗的那次 re-run。之後每次 push 到 `main` 就會自動上線，不用再碰設定。

（workflow 沒有用 `configure-pages` 的 `enablement: true` 自動開，因為那需要 token 有 repo administration 權限，預設的 `GITHUB_TOKEN` 沒有。）

所有資源都用相對路徑，所以 repo 叫什麼名字都能跑（網址會是 `/<repo 名>/`）。QR 編的網址是從投影端當下的網址推出來的，沒有寫死任何 domain。

同一天辦兩場、不想兩場撞題的話，投影端網址加上 `?s=A7K3`（隨便一組字母數字），QR 會自動把它帶給手機。不加的話當天所有手機會用日期算出同一個牌序。

## 常見狀況

| 狀況 | 怎麼辦 |
|---|---|
| 比劃猴不小心重整手機 | 會跳出「要接著玩嗎」，按了就回到同一副牌、同一題 |
| 手機螢幕自己暗掉 | 按「開始比」時會自動要求保持喚醒；不支援的瀏覽器會出現提示，請他把自動鎖定調長一點 |
| 某組手機沒電 | 從結算頁的「重新設定」換一支手機重選同一個組號即可 |
| 現場沒網路 | 只要之前開過一次就能離線玩（Service Worker 需要 https，GitHub Pages 本來就是） |
| QR 掃不到 | 直接念投影幕下方那行網址 |
| 想讓某組多一點時間 | 投影端按 <kbd>+</kbd>，全場一起加 |

## 本機測試

Service Worker 和螢幕喚醒都需要 https 或 localhost，`file://` 開會少這兩個功能。起一個本機伺服器再測：

```bash
npx serve .
```
